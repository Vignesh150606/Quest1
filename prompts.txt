Plus the repo-init commands for https://github.com/Vignesh150606/Quest1.git.
Why: Enforced the phase discipline from PHASES.md against an agent's natural tendency
to run ahead, and -- importantly -- demanded evidence of a real local run rather than
an asserted one, plus an explicit escalate-don't-silently-edit rule for the one test
file that was pre-written.

Outcome: Phase 0 passes. Four real environment problems surfaced, none of which were
predictable from reading the files:
  1. `videocr-PaddleOCR @ git+...` was rejected by pip -- the repo's package metadata
     declares the project name `videocr`, and pip refuses a requirement whose name
     doesn't match the built metadata. Fixed to `videocr @ git+...`, and pinned to
     commit b56af75 rather than tracking a moving HEAD.
  2. `paddleocr==2.10.0` does not declare `paddlepaddle` as a dependency but imports it
     at module load, so `import paddleocr` failed with ModuleNotFoundError. Added
     `paddlepaddle==3.0.0` explicitly (2.6.2 is built against numpy 1.x and would have
     forced a downgrade of the rest of the stack).
  3. ffmpeg/ffprobe were not present on the machine at all -- installed via
     `winget install Gyan.FFmpeg` (v9.0).
  4. **Flagged, not fixed** (per the stop-and-escalate rule): `paddle` and
     `ctranslate2` (faster-whisper's backend) each ship their own copy of
     `libiomp5md.dll`, the Intel OpenMP runtime. Importing paddle first poisons the
     process and ctranslate2 then fails with `OSError: [WinError 127]`. The reverse
     order works. tests/test_environment.py passes only because it happens to import
     faster_whisper before paddleocr -- it asserts nothing about the ordering
     constraint that makes it pass. Left unmodified pending the user's decision, since
     the instruction was to flag rather than silently edit that file.
Also pinned the remaining direct dependencies to the versions actually verified here,
and confirmed the file reproduces from a clean venv (not just the already-warm one).
